Release Differences

Compare the repositories and commits represented by two releases, then follow repository, commit, and work-item links for more detail.

Release Differences Sample

The page lists every commit between the To release and the From release, grouped by repository. The sample below has Show Pending turned on, so work newer than From is listed above it, one group per origin, newest first: Needs build for commits newer than the latest successful build, New for commits that are built but not yet in any release, and one group per release newer than From. With Show Pending off, only the commits between To and From are shown.

Notable Features

  1. See commits across all repositories required to build the site or API to be included in the current release (not just commits isolated to the site or API repository)
  2. Obeys the same From and To release resolution rules as the Release Pipeline. Use the section-head pickers for historical audits, or see From and To Detection for the exact rules.
  3. Show Pending in the section head shows additional release candidates newer than the current From release and commits that have not been published yet.
  4. View any commit on TFS via the commit hash link.
  5. View associated TFS work items via the #work-item reference in commit comments.
  6. View complete commit comment via details button link when comment has been truncated.
  7. Collapse anything you have finished with: the chevron on a repository header folds that repository's commits away, and with Show Pending on, the chevron on a release group folds the whole release. Commit headers stay put while you scroll.
  8. Commits waiting for a build are also surfaced in What's Happening; Release Differences itself does not badge in the rail.
