Notable Features

  1. Supports 2 environment (QA/PROD) or 4 environment (DEV/QA/UAT/PROD) CalcEngines showing exactly where the 'latest' CalcEngine is running
  2. Use the dropdown to filter CalcEngines by environment or all CalcEngines requiring a production move.
  3. Blocked Promotions (full pipelines only) shows every CalcEngine that cannot currently move forward, for either reason: a later environment is running a higher version than the one behind it, so there is nothing valid left to promote until the earlier environment catches up; or the upper file is checked out, which stops TFS's automatic Release Pipeline from promoting it.
  4. Displays checkout user (including Promotion blocking during TFS's automatic Release Pipeline) if CalcEngine checked out. Clicking chip checks in CalcEngines (forcibly for other users).
  5. Quick filter by CalcEngine name or checkout user name.
  6. Check Mine In checks in every CalcEngine you currently hold, in one confirmed action. It appears only while you hold at least one, and counts files rather than rows - a CalcEngine and its upper counterpart are checked out independently.
  7. Approve and Promote CalcEngines to the 'next environment' when ready. Both ask for an authority email - the person signing the move off - prefilled with your KAT Management Site email. It cannot be left blank, and it cannot be the person whose file is moving: the Approval Authority may not be whoever uploaded the test CalcEngine, and the Promotion Authority may not be whoever uploaded the live CalcEngine.
  8. Hover over environment chips to see their state, who uploaded, approved, or promoted and when each environment state occurred. UAT reports a promotion only when the version arrived by promotion - uploading a test version directly replaces that history, so the chip says uploaded instead.
  9. Download CalcEngines or view their version history across environments via action buttons next to each CalcEngine.
  10. Jump straight to a CalcEngine on the Conduent Management Site via the Conduent button next to each CalcEngine.
Conduent Management Site

The Conduent button opens the management site in your default browser, not inside Command Center. It appears in two places, and where you click it decides where you land.

Next to a CalcEngine - opens CalcEngine Management with that file already selected: .../default.aspx?startPage=lnkCalcEngineManagement&startCE=Conduent_Nexgen_SAMPLE_BRD_SE. The startCE value is the CalcEngine name without its file extension, and always the base file - never the _PROD_ variant.
On the KPI tile - opens the management site's home page, with no CalcEngine selected. This button is present even when the KPI has nothing to show, which is the point: it is how you get to the site when you are not signed in to KAT DataStore yet.
Download Preferences

When downloading CalcEngines, by default files are downloaded to your Downloads folder. You can set the Always Replace and Auto Open settings as you desire.

Always Replace - Automatically replaces existing files without prompting for new file name. Default is false.
Auto Open - Automatically opens the CalcEngine after download in Excel. Default is false.

Note: Once these settings are set to true, the only way to reset them is to use the pencil in the first row of the Work Items bar opens the settings file in VS Code for direct editing.

CalcEngine Filter Expressions

By default, sites already have a filter expression defined that includes known CalcEngines at time of latest release. You can modify the expression filter in the 'CalcEngine Filter' input in the header bar's filter row.

Expression Rules

  1. Filter expressions are comma-separated and use OR logic when multiple expressions are provided.
  2. A plain value simply matches an exact CalcEngine name. See first example below.
  3. Instead of a plain value, the following commands are available: StartsWith:pattern, EndsWith:pattern, or Contains:pattern. See second example below.
  4. Chain commands within a single expression with ! for AND NOT logic. See third example below.
  5. To make a chained command be simply AND logic, prefix a later command with ^. See fourth example below.
Filter Result
Conduent_Nexgen_SAMPLE_BRD_SE.xlsm Matches exact name of a CalcEngine.
StartsWith:Conduent_Nexgen_ Names beginning with that prefix.
StartsWith:Conduent_Nexgen_!EndsWith:BRD_SE Starts with the prefix but does not end with BRD_SE.
StartsWith:Conduent_Nexgen_!^Contains:_BRD_SE. Starts with the prefix and contains _BRD_SE.

Version history

Linked work-item references open in TFS, and each checkout line identifies its filename and current owner. The base CalcEngine (DEV/QA) and its production-suffixed counterpart (UAT/PROD) have separate checkouts, so the same owner can appear twice.

History starts with one request to the lower CalcEngine, spanning the lowest through highest version currently shown in the environment grid. For four environments, if both UAT and PROD versions are present in that history, no upper request is needed.

Recognizing probable hotfixes

A direct upload to the upper CalcEngine can introduce versions that do not exist in lower history. A warning triangle marks these as probable patches.

  1. If PROD is already in lower history but UAT is missing, fetch upper history between those two environment versions. Add upper-only versions with patch warnings.
  2. If the lowest upper version is missing and is older than the oldest lower result, look back one decimal increment in lower history. For example, an oldest result of 1.1636 means a lookup from 1.1635 through 1.1636. Take the nearest strictly older lower version; use it as the baseline only if it is below the lowest upper version.
  3. Fetch upper history from that baseline (or the lowest upper version if no baseline was found) through the oldest lower result, extending the upper end when needed to include UAT/PROD. Merge newest first, keeping lower's entry when the same version appears in both histories. The confirmed lower baseline is not a patch.

If lower history is empty, fetch the known UAT/PROD range and mark its rows as probable patches. With only one populated upper environment, that fallback requests its single version. The lookup makes at most three history requests; a failed request is shown as an error, not as an empty result.

The example below is an illustrative excerpt: QA is 1.1678, PROD is 1.16354, and DEV/UAT are empty. The lookup finds the shared baseline 1.1635 and brings back all four probable patches, 1.16351 through 1.16354.

This is a version-number heuristic, not a file-content comparison. A hotfix that reuses a lower version number cannot be distinguished; older upper-only changes are not searched when the current upper versions already exist in lower history. The backward lookup checks one decimal increment only, so skipped numbers or unusual numbering can leave the baseline undiscovered. Such cases retain the known upper minimum rather than guessing an older baseline.
