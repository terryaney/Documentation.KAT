Creating Queries Views

Follow the steps below to link TFS queries to KAT Command Center.

Work Items
  1. Visit TFS Work Items.
  2. Create a new query or select existing query under 'My Queries' (or select existing under 'KAT Queries')
  3. After selecting a query, the address will be something like .../_workitems?id=00000000-0000-0000-0000-000000000001&_a=query. Copy the query ID (i.e. 00000000-0000-0000-0000-000000000001).
  4. In KAT Command Center, click the add query button (shown above).
  5. Fill in the configuration shown below and save it

Active Within
When greater than 0, filters query results to items you revised within that many days. Clear to show all.
A TFS query can only ask about an item's latest revision (Changed Date, Changed By = @Me), so it can't answer "did I touch this in the last N days" - an item you worked yesterday drops out the moment someone else edits it, and an item you never touched shows up because you happened to be the last one in. Active Within instead reads each item's full revision history and keeps the item if any revision in the window is yours.
That accuracy costs one extra API call per item in the query. Every query makes that call eventually - it is the same read that fills in comments for the filter - but for the others it happens in the background after the grid is on screen, while this setting has to wait for it before the grid can be drawn at all. Answers are cached per item and reused until the item's changed date moves, which makes repeat refreshes nearly free, but the first run on a large query is noticeably slower - leave it clear unless the query is one you filter down this way. The chip's severity, priority, old, and tag counts are all computed after this filter, so they describe your active items rather than the whole query.
Show Tag Counts
Shows KAT- prefixed tag totals above the grid and lets those tags filter rows (useful to turn off when the majority of result rows have unique tags).

Notable Features

  1. Query results pane has action bar for refresh, view in TFS, return triaged tasks to assigners, edit configuration, and delete
  2. The reply icon acts on many rows at once - see Return Tasks below
  3. Refresh every query at once with the ↻ button on the bar, or Ctrl+Shift+W from anywhere in the app
  4. Clickable tag count chips to filter list; each row shows its own tags as one chip beside the title
  5. Assigned By names whoever handed the item over - the owner before the current one, or the person who created it if it was never reassigned. It is the column that answers "who is waiting on me for this".
  6. Quick filter box at the left of the action bar - a case-insensitive contains match across the title, description, tags, assignee, assigned by, and comments. It stacks with the tag chips rather than replacing them, so you can narrow by tag and then by words. A count under the last row says how many of the query's items are showing. It survives a refresh and clears when you switch queries.
  7. Descriptions and comments are not in the original query - they are fetched in the background once the grid is on screen. While that is still running, typing in the filter shows a note saying which fields are not being searched yet. It goes away on its own as the data lands.
  8. Toggling to a chip re-runs that query. The grid paints instantly from what was already fetched, then corrects itself a moment later, so what you open is what the query says right now.
  9. When a query changes while you are looking at it - you refreshed, or the rolling background re-check found something - the grid animates rather than jumping: a row that has left fades out, and a new row fades in and then flashes its border. Rows being animated cannot be clicked - wait for the animation to finish. Chip counts update either way, so a query you are not looking at still tells you something happened.
  10. Opening a work item you have opened before is instant. The first open has to fetch the formatted description and full discussion, which the grid does not carry.
  11. Either way the modal reconciles against the server after it opens. If something you were already looking at has since changed, the new value replaces it and a note appears in the header banner - dismiss it with the X or leave it, it clears itself after three seconds. Nothing is announced on a first open, because there was nothing on screen to be wrong.
  12. 'Click to copy' work item IDs to easily share/commit
  13. Sort data by clicking column headings
  14. Clickable title to open work item detail
  15. Context menu for direct actions on specific work item
  16. Keyboard navigation over the rows - see Keyboard navigation below

Keyboard navigation

With a query open, the grid can be driven from the keyboard without reaching for the mouse. The keys match GitHub's, so they should already be in your fingers. They also work when focus has landed on the window's own toolbar rather than the page - after clicking Refresh, for instance - so you don't have to click back into the grid first. The exception is when you are typing in a box or a drop-down, where a letter means what it always means.

KeyDoes
jMove down one row, wrapping from the last row back to the first. With nothing selected yet, selects the first row.
kMove up one row, wrapping from the first row round to the last. With nothing selected yet, selects the last row.
oOpen the selected row's work item detail - the same thing clicking its title does. Does nothing when no row is selected.
cOpen Add Comment against the selected row.
rOpen Return Task against the selected row.
tOpen Triage against the selected row.
xOpen Close Task with State set to Closed. Available on every work-item type, including from the row's right-click menu.
SpaceTick or untick the selected row's checkbox while a batch flow is open - see Return Tasks below. Stays the browser's page-scroll key at every other time.
EscClear the selection. Only when no modal is open; while one is, Escape closes that instead.

The selected row is marked with a violet bar down its left edge - the first row of the grid under View Query Results shows it. The first keypress scrolls the query results into view if they had been scrolled past, and the grid keeps the selected row on screen as you move.

Only rows you can actually see are visited, so the tag chips and the quick filter box narrow what j and k walk through. Sorting keeps your selection on the row you picked - it just moves with it. Switching or refreshing a query clears the selection, as does narrowing the rows.

o, c, r, t and x are shown in the row's right-click menu, so the menu is also where you find them.

c, r and t keep working with a work item open: from the Work Item Detail window they act on the item you are reading, which is the same thing its three header buttons do. They stop there — once a comment modal is up, the letters are just letters again.

x also opens Close Task for the item in the detail window. Like the other action keys, it works when focus is on the WPF toolbar and is ignored while typing or while another modal is open.

That window adds three letters of its own, for the header buttons that only read:

KeyDoes
iCopy the work item ID - the same thing clicking #1234 in the header does.
vView in TFS - opens the item in your browser.
sShare - copies a link to the item.

Each one presses the button itself, so the Copied confirmation appears on the button you would have clicked. They follow the same rule as c, r and t: not while you are typing in a field, and not once a comment modal has opened over the top. All six also work when focus is still on the window's own toolbar — opening an item with o leaves it there, so you never have to click into the item first.

The keys are ignored while you are typing in a field and while any modal is open, so they never fire in the middle of a comment.

Inside a comment modal there is one key of its own: Ctrl+Enter presses OK, from any field, including in the batch Return Task modal. It does nothing until you turn on Submit on Ctrl+Enter in Settings — off by default, because a comment box is somewhere you type freely and a chord that submits from inside one should be something you asked for.

Comment, reassign, or change State

You may comment, reassign, change State, change Triage, or combine them. Add Comment, Triage, and Return Task require at least one actual change. Close Task requires a changed, nonblank State even when you enter a comment. Selecting the current assignee is not a reassignment.

The field order is full-width Reassign To, then Comment, then State and Triage side by side. The same modal has four variants; Close Task is available from the row's right-click menu or x, and the other three also have detail-header buttons:

The four comment defaults are yours to set in Settings - the pencil in the app header. They are blank until you set them. State and Triage are written only when you change them from what the item already has, so a prefill that matches costs no revision, and a blank one never clears a value. An unrecognized current State falls back to leave unchanged. Previous owner means whoever owned the item before its current owner - the person who handed it over - falling back to its creator when it has never changed hands, and suggesting nobody when that would be you.

Ctrl+Enter presses OK from any field in this modal once Submit on Ctrl+Enter is turned on in Settings.

Notable Features

  1. Markdown help starts hidden on every open. Click See supported comment markdown. to replace that link with its callout. The small X beside Comment Markdown hides the callout and restores the link.
  2. The assignee list is in two sections: everyone who has ever created or owned this item, alphabetically, then your team members. Type to search every identity beyond those.
  3. Opened from the Work Item Detail modal, a successful save closes that modal too when you reassign the item or your comment contains the word done - either way you are finished with it.
  4. Comments support bold, italics, underline, inline code, fenced code blocks, and safe links via Markdown.
  5. Raw HTML is not permitted and encoded as literal text.

Supported State Transitions

  • Bug: Proposed to Active or Closed; Active to Proposed or Resolved; Resolved to Active or Closed; Closed to Active.
  • Task: Proposed to Active or Closed; Active to Proposed, Resolved, or Closed; Resolved to Active or Closed; Closed to Active or Proposed.
  • Feature: Proposed to Active, Closed, or Resolved; Active to Proposed, Resolved, or Closed; Resolved to Active or Closed; Closed to Active.
  • Requirement: Proposed to Active, Closed, or Resolved; Active to Proposed, Resolved, or Closed; Resolved to Active or Closed; Closed to Active.

Feature and Requirement's Proposed to Resolved transition passed validation but is not advertised in TFS metadata. Other transitions follow the type metadata; individual item rules may still reject a change. No intermediate saves are attempted after arbitrary errors.

Choosing Closed for an Active Bug automatically saves Resolved, then Closed, in any comment-modal variant. Comment, reassignment, and Triage go only in the final save. These are two revisions, not an atomic update. If closing fails, the modal stays open with your inputs retained and the last confirmed State updates to Resolved. Retry skips that already-completed transition. A timeout may mean the final save landed without confirmation; check TFS before retrying if the outcome is uncertain. State changes guard against a changed State or type on the server and are not automatically retried.

Closing a Proposed item sets its Reason to Rejected. TFS chooses the Reason; the dialog does not override it. For a Task, Active to Closed means Complete and Does Not Require Review/Test; Resolved to Closed means Review/Test Passed.

State accepts Active, Closed, Proposed, and Resolved. Blank or unchanged State creates no State update. In a Close Task dialog this fails validation, even with a comment entered. Alt+S focuses State, alongside Alt+C for Comment, Alt+A for Reassign To, Alt+T for Triage, and Alt+O for OK.

Comment Markdown supports **bold**, _italics_, __underline__, `inline code`, fenced multiline code blocks, and [anchor](https://example.com). Raw HTML is shown as text.

Return Tasks

The reply icon puts the grid into select mode: a checkbox appears before every ID, the icon itself is replaced by its confirmation, and the rest of the toolbar keeps working. Only the rows already at Triaged offer a checkbox - the work you just finished - and they go back to whoever handed them over. Yes opens one editable block per ticked item.

Ticking can be done from the keyboard: j and k move down and up the rows, and Space ticks the one you are on. Rows that are not yet Triaged are still there to read but have no checkbox, so Space does nothing on them. See Keyboard navigation above.

The All box on the confirmation ticks every row currently on offer, and clearing it unticks them. It follows the rows rather than leading them: untick one and it shows the partial (dash) state, tick the last one and it fills in. A tag chip or the quick filter narrows what All speaks for, so it covers the rows you can see.

Notable Features

  1. Every field is prefilled: Return To with whoever owned the item before you, Triage with Pending, and the comment with your Default Return Task Comment from Settings (blank until you set it). Change or clear what doesn't apply.
  2. Return To is the same combobox as the single-item form - that item's own participants first, then your team members, and type to search every identity beyond them.
  3. Return To comes up blank when there is genuinely nobody to return the item to - you created it, you own it, and it has never changed hands. Pick someone yourself.
  4. Only the comment is optional. An item without a Return To blocks the submit and is marked in place.
  5. Every item is written concurrently as one comment-plus-reassign-plus-Triage change, so the assigner sees a single revision rather than three.
  6. A clean run closes the form and updates the grid. If some items fail, the ones that landed disappear from the form and the rest stay with their error attached - press OK to retry just those.
