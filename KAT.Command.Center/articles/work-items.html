Work Items

KAT Command Center can render your saved TFS queries directly in Work Items. Each query is an entry under Work Items in the rail, whose badge counts the items that need attention, and opening one shows its counts in the section header, summarizing pressure at a glance 4 items‼1!4⟳1.

Look up a Task by ID

Easiest way to use KAT Command Center's Work Item's capability is via task lookup. Select Work Items in the rail; the lookup is at the right of its header whichever query is open.

  1. Enter a positive numeric ID in Task ID Search.
  2. Press Enter or click the magnifying glass.
  3. Review description, fields, history, attachments, and actions in the Work Item Detail viewer.

Creating Queries Views

Follow the steps below to link TFS queries to KAT Command Center. Queries are added, edited and removed on the Work Items page of Settings.

  1. Visit TFS Work Items.
  2. Create a new query or select existing query under 'My Queries' (or select existing under 'KAT Queries')
  3. After selecting a query, the address will be something like .../_workitems?id=00000000-0000-0000-0000-000000000001&_a=query. Copy the query ID (i.e. 00000000-0000-0000-0000-000000000001).
  4. In KAT Command Center, open Settings with the Settings button in the app bar, choose Work Items, and click Add above the Queries list (shown above).
  5. Fill in the configuration shown below, then press the footer's Save to put the query in the list.
  6. Press Save again to save Settings. The new query appears under Work Items in the rail without a refresh.

While the Add/Edit query pane is open, the footer's Cancel and Save act on this one query - the Query Edits label above them says so. To change a query later, press Edit on its row. No query edits, additions, or deletions are saved until you press Save from any of the main Settings pages, and Cancel discards all of it. See Settings for explanation of Work Query settings.

View Query Results

Select a query under Work Items in the rail to view, filter, and sort its results. The section header takes the query's name and shows how many items it has, followed by one chip per indicator the query counts - see Settings for the thresholds. Clicking Work Items itself opens the page; its caret shows or hides the list of queries.

Notable Features

  1. The open query's own actions - Return Triaged (see below) and View Query In TFS - sit in the header beside the lookup, and its filter box and Tags picker sit on the row beneath. In a narrow window the lookup and those actions move into the header's ⋯ menu.
  2. Indicator chips filter. Click a chip beside the item count to show only the items it counts; click it again to stop. Several chips together show items matching any of them, and combined with the Tags picker and the filter box, rows must match all of them. A chip whose count drops to zero stops filtering. Each query keeps its own filter text, tags, chips and sort, so switching back to a query brings them back.
  3. A query set to Hide query when no work items present is left out of the rail while it is empty, unless it is the query you have open.
  4. The header's ↻ re-runs every query at once (Ctrl+Shift+W); Ctrl+Shift+Q re-runs just the open one.
  5. Each row's ⋯ button, before its ID, opens a menu of direct actions on that work item. Sort by clicking column headings.
  6. Quick filter - a case-insensitive contains match across the title, description, tags, assignee, assigned by, and comments. Descriptions and comments are not in the original query - they are fetched in the background once the grid is on screen. While that is still running, typing in the filter shows a note saying which fields are not being searched yet.
  7. The Tags picker lists every tag in the query with how many items carry it, KAT tags first. Tick several to show items carrying any of them, or choose All for items with any tag or Missing for items with none.
  8. 'Click to copy' work item IDs to easily share/commit
  9. Assigned By names whoever handed the item over - or the person who created it if it was never reassigned. It answers "who is waiting on me for this".
  10. Opening a query re-runs it. The grid paints instantly from what was already fetched, then auto-corrects itself if the underlying data has changed; the rail shows animated dots on the query while it checks. The same happens if a background re-check found something. Every query's rail badge updates - even a query you are not looking at still tells you when something changed. See Reading the Dashboard for what the badges count.
  11. See Keyboard Shortcuts for navigation and action shortcuts.

Work Item Detail

Work Item detail displays all task details, comment history and access to download attachments. If an item has a client KAT tag but is not itself tagged KAT Spec Sheet, matching spec sheet attachments are shown in a separate row.

Notable Features

  1. 'Click to copy' ID and Title to easily share or use in commit comments and messages/emails
  2. The banner carries who has it and how it got there - Assigned To, Assigned By, Created By and when it last changed - then the classification it was filed under: Type / State, Priority / Severity, and its tags.
  3. The header's ⋯ menu holds Edit Task, Triage, Return Task and Close Task, then View in TFS, Copy Link and Copy ID. The row's ⋯ menu has the same actions.
  4. Attachment chips enable file download. If a task tag matches a spec sheet attachment, it will be displayed in a separate row for easy access.
  5. Keyboard warriors rejoice. Keyboard Shortcuts provide quick access to all the actions you need to manage a work item efficiently.
  6. Comments show newest first with who wrote them and when (hover a time for the exact date). Click a person's avatar to show only their comments; click them again to show everyone. Newest/Oldest flips the order. A long description or repro steps is trimmed with a Show full link, such as Show full repro steps.
  7. People show as coloured initials, replaced by their TFS profile photo a moment after the modal opens if they have one. The photos load in the background, so they never hold the comments up, and anyone without a photo simply keeps their initials.
  8. Related Work, Commits and Builds tabs show linked work items, associated commits and integrated builds; each tab shows its count.
  9. History shows how the item got where it is. Two lanes along the top trace its State and Owner, one stop per change with how long each lasted; a long lane collapses to +N, which expands it (Show less folds it back). Below, every save is listed newest first by day, with each field's old and new value and any link added or removed. One person's back-to-back saves show as one entry, led by "N saves"; the window is set in Settings > Work Items > History. A save that added a comment has a comment button that opens that comment on the Details tab. Links TFS added on its own, such as a build that integrated the item, are marked automatic.

Edit, comment, reassign, or change State

Editing happens inside Work Item Detail: the details give way to a form, with the item's comments below it. There are four ways in - Edit Task, Triage, Return Task and Close Task - from the detail's ⋯ menu, the row's ⋯ menu, or keyboard shortcuts. They open the same form and differ only in what they fill in.

Notable Features

  1. The form holds Title, Assigned To, Tags, State, Triage, Priority, Severity (Bugs only), a Comment and Attachments. Tags offers the site's KAT tags, then the Additional tags from Settings > Work Items and any the item already has.
  2. Only the fields you change are written, together with the comment and any attachment changes, as one revision. Saving with no change and no comment simply leaves the form.
  3. Title is always required. A field that already had a value cannot be emptied, Return Task needs someone in Assigned To, and Close Task needs a State other than the current one. Problems are marked on the field and counted beside the buttons.
  4. Edit Task returns to the details after saving; the other three close the detail. Opened straight from the grid, saving or cancelling closes the detail.
  5. Cancel or Esc leaves the form. In a comment you have changed, the first Esc asks whether to discard; press it again to discard, or click the × to keep editing.
  6. Saving checks that nobody changed the item since the form opened. If someone did, nothing is saved: the fields they changed take the new values, a callout lists what changed, and your comment and other edits stay for you to review and save again. If nothing changed, the save is retried once on its own. If that fails too, the form locks; use Copy Comment to keep your text, then Cancel.
  7. Close Task is unavailable on an item that is already Closed.
  8. State lists only the States the item can move to from its current one (see Work item state transitions). If TFS still refuses a value, that value is removed from the field's list and the field is marked, so you can pick another.
  9. Below the form, Edit Task shows two tabs: the item's Description (or Repro Steps) and its Comments. Comments is selected when the item has any. Comments are newest first and trimmed to a few lines; Show all comments, below them, expands them and brings back the sort and person filter. Comments that arrived while you were editing are marked New. Triage, Return Task and Close Task show only the comments.
  10. The assignee list is in two sections: everyone who has ever created or owned this item, alphabetically, then your team members. Type to search every identity beyond those.

Comment Markdown and pasted images

Comments, the Return Triage Tasks comments and a new work item's description accept **bold**, _italics_, __underline__, `inline code`, fenced multiline code blocks, and [anchor](https://example.com). Raw HTML is shown as text.

In the form, See supported comment markdown. opens a callout with these rules; its × hides it again.

In the form's comment, a Return Triage Tasks comment or a new work item's description, press Ctrl+V with an image on the clipboard to add it. A marker such as ![image-1.png](pasted:1) appears where you pasted; the image is uploaded to TFS when you save and shown in its place. Delete the marker to drop the image. Images up to 4 MB are accepted. If an upload fails, nothing is saved and the form stays open so you can try again; in Return Triage Tasks only that task stays, for Retry. Copy Comment copies the text only.

Attachments

The edit form and the new work item dialog list the item's attachments as chips, with a full-width Click to add files or drop in this window button below them.

  1. The button picks files; you can also drop files anywhere on the open form or dialog. Files up to 4 MB each are accepted.
  2. Until you save, each change is marked like a diff: a green + for a file you added, a red − for an attachment you removed, and a swap icon for an attachment replaced by a file with the same name.
  3. The × on a saved attachment marks it removed; on an added file it takes the file off the list. A removed or replaced attachment shows an undo icon instead, which puts the original back as it was. Nothing changes on TFS until you save; Cancel keeps the attachments as they were.
  4. Saving uploads the new files first. If an upload fails, nothing is saved and the form stays open so you can try again.

Update a Spec Sheet by dropping it

Drop an updated Spec Sheet workbook (.xlsx) anywhere on the app, with no dialog open, to attach it to the Spec Sheet task it belongs to.

While a single .xlsx file is dragged over the app, the app's splash screen shows Drop Spec Sheet to prepare a task update. It disappears if you leave the window. After the drop, the splash shows Processing Spec Sheet until the task opens. If the file can't be used, the splash closes and a warning explains why. The splash is not shown over an open dialog.

  1. The Version on the workbook's Plan Info tab is read, then the task is found: it must be tagged KAT Spec Sheet and already have an attachment with the same file name. Exactly one task must match.
  2. That task opens in Edit Task with its Title set to {Client} Spec Sheet v{Version} and the dropped workbook staged as a replacement for the matched attachment. The client name comes from the file name: for MHA-Spec-AcmeCorp.xlsx it is Acme Corp.
  3. Review the changes and save, or Cancel to leave the task unchanged.
  4. Reading the workbook needs you signed in to the KAT DataStore. If the file can't be used - more than one file, not an .xlsx, no Plan Info tab or no Version on it, or no single matching task - a warning in the footer says why.

Return Triage Tasks

The Return Triaged button puts the grid into select mode. It disables itself and adds a row below the filters with Return Tasks:, an All box, how many are ticked, Continue and Cancel. A checkbox appears before every applicable ID, but only the rows already at Triaged offer one: the work you just finished, which goes back to whoever handed it over. Continue opens the dialog below. Dismissing it keeps the ticks so you can change them. Cancel or Esc leaves select mode.

Keyboard warriors, see Keyboard Shortcuts for details on how ticking and navigation can be done from the keyboard.

Notable Features

  1. Every field is prefilled: Return To with whoever owned the item before you, Triage with Pending, and the comment with your Default Return Task Comment. Change or clear what doesn't apply.
  2. Only the comment is optional. An item without a Return To blocks the submit and is marked in place. Pressing OK closes the dialog, and the row reads Processing… until every item is written; a Return cannot be cancelled once it starts, so its Cancel is hidden. Items that failed, or that changed since you ticked them (those are refreshed, not saved), are marked in the grid and listed with their reason above it. Select mode then ends. Retry on that list reopens the dialog with only those items, filled in with what you submitted. The list, and the chance to retry, are cleared by its ×, by pressing Return Triaged again, by submitting another Return, or by switching queries.
  3. Every item is written concurrently as one comment-plus-reassign-plus-Triage change, so the assigner sees a single revision rather than three.
