Look up a Task by ID

Easiest way to use KAT Command Center's Work Item's capability is via task lookup.

Work Items
  1. Enter a positive numeric ID in Task ID Search.
  2. Press Enter or click the magnifying glass.
  3. Review description, fields, history, attachments, and actions in the Work Item Detail viewer.

Query Edits

While the Add/Edit query pane is open, the footer's Cancel and Save act on this one query - the Query Edits label above them says so. To change a query later, press Edit on its row. No query edits, additions, or deletions are saved until you press Save from any of the main Settings pages, and Cancel discards all of it. See Settings for explanation of Work Query settings.

Notable Features

  1. Query results pane has action bar for refresh, view in TFS, and Return Triaged tasks - see below
  2. A query set to Hide chip when no work items present has no chip while it is empty. If every query is empty, the row of chips goes too
  3. Refresh all queries at once or the currently open query by clicking the appropriate ↻ button.
  4. Context menu for direct actions on every work item row and sortable data by clicking column headings
  5. Quick filter - a case-insensitive contains match across the title, description, tags, assignee, assigned by, and comments. Descriptions and comments are not in the original query - they are fetched in the background once the grid is on screen. While that is still running, typing in the filter shows a note saying which fields are not being searched yet.
  6. Tag count chips for easy way to filter results even further based on assigned tags
  7. 'Click to copy' work item IDs to easily share/commit
  8. Assigned By names whoever handed the item over - or the person who created it if it was never reassigned. It answers "who is waiting on me for this".
  9. Toggling to a chip re-runs that query. The grid paints instantly from what was already fetched, then auto-corrects itself if the underlying data has changed. The same happens if a background re-check found something. All query chip counts update - even a query you are not looking at still tells you when something changed.
  10. See Keyboard Shortcuts for navigation and action shortcuts.

Work Item Detail

Work Item detail displays all task details, comment history and access to download attachments. If an item has a client KAT tag but is not itself tagged KAT Spec Sheet, matching spec sheet attachments are shown in a separate row.

Notable Features

  1. 'Click to copy' ID and Title to easily share or use in commit comments and messages/emails
  2. The banner carries who has it and how it got there - Assigned To, Assigned By, Created By and when it last changed - then the classification it was filed under: Type / State, Priority / Severity, and its tags.
  3. Header action bar provides easy access to view on TFS, direct link sharing, and the three comment variants - Triage, Return Task, and a plain Add Comment.
  4. Attachment chips enable file download. If a task tag matches a spec sheet attachment, it will be displayed in a separate row for easy access.
  5. Keyboard warriors rejoice. Keyboard Shortcuts provide quick access to all the actions you need to manage a work item efficiently.
  6. Comments show newest first with who wrote them and when (hover a time for the exact date). Click a person's avatar to show only their comments; click them again to show everyone. Newest/Oldest flips the order. A long description is trimmed with a Show full description link.
  7. People show as coloured initials, replaced by their TFS profile photo a moment after the modal opens if they have one. The photos load in the background, so they never hold the comments up, and anyone without a photo simply keeps their initials.
  8. Links tab shows related work items, associated commits, and integrated builds.

Comment, reassign, or change State

You may comment, reassign, change State, and change Triage. The same modal has four variants; Triage, Return Task, Add Comment, and Close Task. Each is available from the row's right-click menu, detail-header buttons, or keyboard shortcuts. All essentially perform the same action of submitting your changes but vary by the defaults they provide.

The four comment defaults are yours to set in Settings > Work Items (along with Submit comment dialogs with Ctrl+Enter). They are blank until you set them. State and Triage are written only when you change them, so a prefill that matches costs no revision, and a blank one never clears a value. An unrecognized current State falls back to leave unchanged.

Notable Features

  1. Markdown help starts hidden on every open. Click See supported comment markdown for inline guidance. Comment Markdown supports **bold**, _italics_, __underline__, `inline code`, fenced multiline code blocks, and [anchor](https://example.com). Raw HTML is shown as text.
  2. The assignee list is in two sections: everyone who has ever created or owned this item, alphabetically, providing quick access to the people that matter most, then your team members. Type to search every identity beyond those.
  3. Opened from the Work Item Detail modal, a successful save closes that modal too when you reassign the item or your comment contains the word done.

Return Triage Tasks

The Return Triage Tasks action puts the grid into select mode: a checkbox appears before every applicable ID. Only the rows already at Triaged offer a checkbox - the work you just finished - and they go back to whoever handed them over.

Keyboard warriors, see Keyboard Shortcuts for details on how ticking and navigation can be done from the keyboard.

Notable Features

  1. Every field is prefilled: Return To with whoever owned the item before you, Triage with Pending, and the comment with your Default Return Task Comment. Change or clear what doesn't apply.
  2. Only the comment is optional. An item without a Return To blocks the submit and is marked in place. If some items fail, the ones that landed disappear from the form and the rest stay with their error attached - press OK to retry just those.
  3. Every item is written concurrently as one comment-plus-reassign-plus-Triage change, so the assigner sees a single revision rather than three.
