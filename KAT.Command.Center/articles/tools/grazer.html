Tools · local search

Grazer

Grazer searches text across named folders on your machine and makes carefully previewed replacements.

Grazer is an independent, manual tool under Tools in the app rail. It searches the configured local folders regardless of the selected site. Searching is read-only; no search runs on a timer or while you type, and files change only when you choose a replace action or Undo. Only the selected root and result mode are remembered. Search terms, custom pattern overrides and results are not saved; custom patterns last for the app session, and a blank override uses the Settings defaults on the next search. Reopening the app never starts a search automatically. On the active Grazer page, F5 searches with the current root, patterns and result mode plus existing chips; it does not add text still in the Search term or Replace term boxes. With no chips, it does nothing.

Set root folders, default patterns, exclusions and safety limits on the Grazer page in Settings. Missing or inaccessible roots are reported, and do not stop other roots from being searched.

Saving or reloading Grazer settings keeps your current results, pending replacement confirmation and Undo. A running search finishes with the settings it started with. Roots, patterns, exclusions, size limits and Git/ZIP/Shared options apply to the next search. New replacements use the current confirmation preferences, and both Replace and Undo check the current Replace read-only files setting before writing.

Searching

Type a literal term in Search term and press Enter to add it as a chip; add up to 100. Enter in Replace term also adds the chip, and Enter in an empty Search term box runs the search. A search term can be up to 512 characters, and replacement text a single line of up to 4,096. A line matches when it contains any term (OR matching); terms are not regular expressions. New chips ignore case and match substrings. Each chip has compact buttons for Match case (Aa) and Match whole word (underlined ab, like VS Code); a highlighted button means the option is on. Whole-word matching requires neither end of the literal term to touch a Unicode letter, digit, combining mark or connector punctuation such as an underscore. For example, cat matches (cat) but not cats or cat_name. The same text can appear more than once only with different matching settings. The red trash button removes a chip. File patterns are wildcards matched against filenames, separated by semicolons, commas or line breaks. Choose a Framework (one of the named roots from Settings, or All frameworks), then a Result mode:

  • Line matches shows matching lines and their line numbers; matching text is highlighted, but terms are not listed per result. Click a line to open the file at that line in VS Code. ZIP-entry lines are informational because archive entries are read-only.
  • File names shows matching files and their matching-line counts. Click a file to open it at its first match in VS Code.
  • Folder names shows distinct folders that contain matching files.

Search submits the chips and filters. Text still sitting in Search term is added as a chip first. While a search runs, Search is replaced by Cancel and every other input, chip and action is disabled. F5 uses the current root, patterns and result mode with existing chips only; pending text is left alone. Clear Results clears the results, the chips and the Search term box. Hide Inputs collapses the search form so the results have more room; Show Inputs brings it back. In a narrow window these header actions move under More actions. See Keyboard Shortcuts for refresh behavior on other pages.

Replace terms

A chip can also carry a Replace term. Leave it blank for a search-only term. To replace with nothing, type exactly <empty>; the chip shows <empty> in italics. Replace terms only apply in Line matches: in the other modes the Replace box is disabled and the replace part of each chip is dimmed, but the term still searches and the replace text is kept.

Replacement works line by line. Search-only terms test the original line. Replace terms then run in chip order, each on the line as the previous replace term left it and each with its own case and whole-word settings, so A → B followed by B → C turns an original A into C.

Progress and completion summary

While searching, the status line shows files visited and matching lines found so far. The completion summary depends on the result mode: Line matches shows retained matching lines, files and repository groups; File names shows files and repository groups; Folder names shows distinct matching folders. The Line matches and File names summaries label repository groups as “folders”; those are grouping headings, not the count of actual directories containing matches. A folder count in Folder names is the count of matching directories. The full-scan counts remain distinct from the retained results after the display limit.

The scan-details strip shows elapsed time, visited folders/files, bytes read and skip reasons. Its tag item counts the search terms behind the results; hover it for the file patterns used, or click it to list the terms. The reasons list first what your configuration excluded (excluded directories and files, Git metadata, duplicate Shared repositories, duplicate paths from overlapping roots, symbolic links and junctions, and ZIP archives disabled in Settings) in that fixed order. Anything that could hide a match, such as unreadable or oversized files, binary files or unsupported encodings, follows by count, highest first, in the attention color. Root problems appear on the Grazer page only, not in What's Happening. Hover or focus a status item for its full description.

Limits and exclusions

Grazer retains at most 2,000 result items in the selected mode. This is a fixed display and replacement-target limit, not a scan limit: Grazer continues scanning, then reports omitted result items and, when applicable, omitted files and folders alongside full-scan totals. Replace All can target only retained, non-dismissed results; the confirmation calls out omitted results that will not be changed. The default file-size cap is 50 MB (1 to 256 MB): ordinary files and ZIP containers are bounded by on-disk size; ZIP entries are bounded by uncompressed size. Oversized, binary or unreadable content is skipped with a visible reason. Text is read as UTF-8 first; a file with no byte-order mark that is not valid UTF-8 is searched again as Windows-1252, so older ANSI sources still match. Only files whose encoding cannot be read either way count as unsupported or malformed.

Shared repositories are often cloned under several sites. With Search each Shared repository once on in Settings (the default), the first copy of each Shared* repository found is searched and later copies are skipped and counted as duplicate Shared repositories. Turn it off to search every copy.

ZIP searching is off by default and can only be enabled in Settings. When enabled, matching text entries are read without extracting them; archives and their entries are never modified. Searching .git metadata is a separate Settings option and is off by default. Directory-name, literal excluded-folder and path-fragment lists are editable there, so exclusions are visible rather than hidden filters.

Results stay hidden until a search returns, and appear in the page itself rather than in a separate scrolling box. Line matches forms a repository group > file > line tree; the file shows its relative folder as a callout, not another tree level. File names forms a repository group > file tree, and Folder names a repository group > matching folder tree. The line and file summaries count repository groups separately from actual matching folders. Collapse All closes every branch in the current tree. Hover a row to dismiss it; dismissing a line, file or folder removes it from the current result set and from replacement. A new search restores dismissed matches.

Replacing

The results are the preview. A line the replace terms change shows as Ln Updated with its Old: text (search terms highlighted) and New: text (replacement values highlighted) beneath it; click the Updated row or its Old text to open that line in VS Code. A line matched only by search-only terms stays an ordinary line row and is never changed.

Hover a repository folder, file or Updated row for its replace button, just before the dismiss button, to replace every Updated line under that row, including collapsed ones. Replace All in the page header replaces every Updated line still in the results. Dismissed lines and results omitted by the 2,000-item limit are never replaced. Replace All appears after a Line matches search, including a cancelled one, that left Updated lines. Replacing always applies the results on screen: editing chips, patterns, Framework or Result mode afterward does not change what is replaced, so search again to preview edited terms.

Before writing, Grazer re-reads each file and compares it with what the search read. If the file changed since the search, it is refused with File changed since search. Search again. Each Updated line is also checked against its Old text before it is replaced. Files keep their encoding, byte-order mark and line endings; a legacy Windows-1252 file is written only when its content round-trips exactly, and a replacement that file cannot represent is refused. Each file is written atomically where supported. Grazer creates no backup files; rely on source control.

Replaced lines leave the results and counts update, as with dismissing; replacing more lines in the same file afterward still works. A line that could not be replaced stays in place with the reason beside it. A fully successful replacement only removes its rows; a partial or cancelled one also reports, for example, Replaced 12 match(es) in 3 file(s); 1 failed and 0 not started. ZIP entries are read-only and never offer replace.

Undoing the last replacement

After a replacement writes at least one line, Undo appears beside the header actions (or under More actions in a narrow window). One click restores every line that replacement actually wrote, whether you replaced one line, one file, a repository or all results. There is no confirmation. If the replacement partly failed or was cancelled, Undo covers only its completed changes.

Grazer keeps one Undo in memory, not in a file. A later replacement that writes any lines replaces it; an attempt that writes nothing keeps the earlier Undo. A new search, Clear Results, restarting the app or starting Undo itself removes it. Undo cannot be retried, even when some files could not be restored.

Undo uses the same safe file-writing checks as Replace. If a file changed after the replacement, none of its recorded lines are overwritten; other files can still be restored. Each line must still contain the text Grazer wrote. Missing, locked, read-only or unsafe files are reported rather than silently overwritten. Files keep their encoding, byte-order mark and line endings.

A green message reports restored lines and files. Those rows remain absent from the current results; search again if you need to see them. Remaining rows stay usable, including further replacements in a restored file. If any lines could not be restored, a separate error box shows the failure count and up to five path/line/reason details, with See log for details for the full list. These messages clear when you start a search, clear results, start another replacement or start Undo.

Undo runs to completion without a Cancel button. Closing the app finishes the current batch of up to four files, then stops before the next batch.

Confirmation and cancellation

Each replace first asks Replace X match(es) in Y file(s)? Settings has a separate switch for a single Updated line (Applying line replacements) and for a file, repository folder or Replace All (Applying file replacements); both are on by default. Turning on Don't ask me to confirm line replacements (or file replacements) in the prompt turns off the matching switch only if you choose Replace; Cancel leaves it alone, and Settings can turn it back on. When Replace All leaves results omitted by the 2,000-item limit, the prompt says how many will not be replaced. Turning confirmation off never skips the preview or the stale-file checks.

Search can be cancelled while reading. Replacement runs in batches of up to four files, and Cancel Apply in the header stops before the next batch while finishing the files already in progress. Completed changes are not rolled back automatically, but Undo can restore them; the status reports how many matches were replaced, failed or not started.
