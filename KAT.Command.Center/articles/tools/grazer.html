Tools · local search

Grazer

Grazer searches text across named folders on your machine and makes carefully previewed replacements.

Grazer is an independent, manual tool under Tools in the app rail. It searches the configured local folders regardless of the selected site. Searching is read-only; no search runs on a timer or while you type, and files change only when you choose a replace action. The selected root, file patterns and result mode are remembered, but search terms, replace terms and result contents are not. Reopening the app never starts a search automatically, and F5 does nothing until you have searched.

Set root folders, default patterns, exclusions and safety limits on the Grazer page in Settings. Missing or inaccessible roots are reported, and do not stop other roots from being searched.

Searching

Type a literal term in Search term and press Enter to add it as a chip; add up to 100. A search term can be up to 512 characters, and replacement text a single line of up to 4,096. A line matches when it contains any term (OR matching); terms are not regular expressions. New chips ignore case and match substrings. Each chip has compact buttons for Match case (Aa) and Match whole word (underlined ab, like VS Code); a highlighted button means the option is on. Whole-word matching requires neither end of the literal term to touch a Unicode letter, digit, combining mark or connector punctuation such as an underscore. For example, cat matches (cat) but not cats or cat_name. The same text can appear more than once only with different matching settings. The red trash button removes a chip. File patterns are wildcards matched against filenames, separated by semicolons, commas or line breaks. Choose a named root or All, then select a result mode:

  • Line Matches shows matching lines, their line numbers and which terms matched. Click a line number to open the file in VS Code. ZIP-entry line numbers are informational because archive entries are read-only.
  • File Names Only groups matching files and reports their matching-line counts and terms.
  • Folder Names Only summarizes matching folders, files, lines and terms.

Search submits the chips and filters. Text still sitting in Search term is added as a chip first. While a search runs, Search is replaced by Cancel and every other input, chip and action is disabled. F5 reruns the last submitted search, not edits made afterward; before the first accepted search, F5 does nothing. Clear Results clears the results. See Keyboard Shortcuts for refresh behavior on other pages.

Replace terms

A chip can also carry a Replace term. Leave it blank for a search-only term. To replace with nothing, type exactly <empty>; the chip shows it as an italic ∅ empty. Replace terms only apply in Line Matches: in the other modes the Replace box is disabled and the replace part of each chip is dimmed, but the term still searches and the replace text is kept.

Replacement works line by line. Search-only terms test the original line. Replace terms then run in chip order, each on the line as the previous replace term left it and each with its own case and whole-word settings, so A → B followed by B → C turns an original A into C.

Progress and completion summary

While searching, the status line shows counts only: folders and files visited, plus line matches, matching files or matching folders depending on the result mode. When the search ends it reads, for example, Completed in 8.5s · Excluded directories (342) · Excluded files (1,358) · Git metadata disabled (170) · Unsupported or malformed text encodings (4). A cancelled search starts with Cancelled after 3.2s, and reaching the result cap adds Limit reached - results are incomplete.

The reasons list first what your configuration excluded (excluded directories and files, Git metadata, duplicate Shared repositories, duplicate paths from overlapping roots, symbolic links and junctions, and ZIP archives disabled in Settings) in that fixed order. Anything that could hide a match, such as unreadable or oversized files, binary files or unsupported encodings, follows by count, highest first, in the attention color. Root problems are listed under the search form and in What's Happening. The line is one ellipsized row; hover it for the full text.

Limits and exclusions

The default cap is 10,000 result rows (Settings allows 1 to 100,000). If it is reached, Grazer stops and marks the results incomplete. The default size cap is 50 MB (1 to 256 MB): ordinary files and ZIP containers are bounded by on-disk size; ZIP entries are bounded by uncompressed size. Oversized, binary or unreadable content is skipped with a visible reason. Text is read as UTF-8 first; a file with no byte-order mark that is not valid UTF-8 is searched again as Windows-1252, so older ANSI sources still match. Only files whose encoding cannot be read either way count as unsupported or malformed.

Shared repositories are often cloned under several sites. With Search each Shared repository once on in Settings (the default), the first copy of each Shared* repository found is searched and later copies are skipped and counted as duplicate Shared repositories. Turn it off to search every copy.

ZIP searching is off by default and can only be enabled in Settings. When enabled, matching text entries are read without extracting them; archives and their entries are never modified. Searching .git metadata is a separate Settings option and is off by default. Directory-name, literal excluded-folder and path-fragment lists are editable there, so exclusions are visible rather than hidden filters.

Results stay hidden until a search returns, and appear in the page itself rather than in a scrolling box. They form a tree of repository folder, file and matching line (in file or folder modes, folder and file or folder leaf), with a badge of matching lines on each row and a summary line under the header. Hover a row to dismiss it; dismissing a line, file or folder removes it from the current result set and from replacement, and a folder disappears once its last child is dismissed. A new search, including F5, restores dismissed matches.

Replacing

The results are the preview. A line the replace terms change shows as Ln Updated with its Old: text (search terms highlighted) and New: text (replacement values highlighted) beneath it; click the line number to open it in VS Code. A line matched only by search-only terms stays an ordinary line row and is never changed.

Hover a folder, file or Updated row for its replace button, just before the dismiss button, to replace every Updated line under that row. Replace All in the page header replaces every Updated line still in the results, including pages not loaded yet. Dismissed lines are never replaced. Replace All appears only after a search that produced Updated lines. If you add, remove or change chips afterward it is disabled until you search again, because replacing always uses the terms of the search on screen.

Before writing, Grazer re-reads each file and compares it with what the search read. If the file changed since the search, it is refused with File changed since search. Search again. Each Updated line is also checked against its Old text before it is replaced. Files keep their encoding, byte-order mark and line endings; a legacy Windows-1252 file is written only when its content round-trips exactly, and a replacement that file cannot represent is refused. Each file is written atomically where supported. Grazer creates no backup files; rely on source control.

Replaced lines leave the results and counts update, as with dismissing; replacing more lines in the same file afterward still works. A line that could not be replaced stays in place with the reason beside it. The status line reports, for example, Replaced 12 match(es) in 3 file(s) · 1 failed. ZIP entries are read-only and never offer replace.

Confirmation and cancellation

Confirm before applying replacements is on by default, so each replace first asks Replace X match(es) in Y file(s). Turning on Don't ask me to confirm replacements in that prompt takes effect only if you confirm; Cancel leaves the setting alone. Settings can turn confirmation back on. Turning it off never skips the stale-file checks.

Search can be cancelled while reading. Replacement runs in small batches, and Cancel stops before the next one while finishing the files already in progress. Completed changes are not rolled back; the status reports how many matches were replaced, failed or not started.
