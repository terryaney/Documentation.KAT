Settings...take control of your experience.

Settings

The Settings button at the right end of the app bar () opens Settings.

  1. Profile page: your KAT Management site credentials, your Conduent network account, and a TFS Personal Access Token (PAT).
  2. Display page: adjust the appearance and layout of the application - theme, density, how the rail collapses, whether Releases and Sentinel are one page or several - and when CalcEngine checkouts and What's Happening items change.
  3. Work Items page: configure your work item queries and workflow used within the application.
  4. Grazer page: configure local search roots, exclusions, result limits, ZIP/Git options, and replacement confirmation.
  5. Repository Status page: choose the folders searched for Git repositories, the ignore patterns, how often status is checked and remotes are fetched, and which Git actions ask for confirmation.
  6. Connections page: manage your application's connections to external services and data sources.

Folder paths in Grazer, the Repository Status roots and the Release folder setting share an editable picker. Type or paste a path, use the up/down arrows and Enter to choose one of up to 25 immediate child-folder suggestions, or press the folder button beside the path; Esc closes the suggestions. These edits stay in the Settings draft until you choose Save; Cancel discards them. Editing a path does not run a Grazer search or rescan repositories; saving changed Repository Status roots does.

Notable Features

  1. On first launch with no PAT, Settings opens on Profile by itself. Nothing asks for credentials in the middle of a refresh. A section whose sign-in is missing or rejected says Needs credentials; fix it on Profile and that section refreshes.
  2. Changes on Display preview immediately in Settings and the dashboard behind it.
  3. You can mix theme families: a light preference does not change your dark preference.
  4. For the keyboard warriors, Ctrl+Enter triggers an immediate save in the Settings dialog.
  5. Validation errors are indicated with a badge count beside its page in the list, so a problem on a page you are not looking at is still easy to find.
  6. Saved settings reach the open dashboard immediately; no refresh is needed.
  7. When a newer build is waiting, an Update available button appears at the bottom of the rail. Pressing it replaces the app and restarts it, so finish what you are doing first.
  8. Show release notes, under the page list, opens What's New. Open settings file opens the saved settings file itself.

Setting Up Access

KAT Command Center needs three sign-ins, all entered on the Profile page of Settings: your KAT Management site credentials, your Conduent network account, and a TFS Personal Access Token (PAT).

TFS PAT

The PAT enables the Release and Work Items management application features. Follow the steps below to set up your PAT for KAT Command Center.

  1. Visit TFS Personal Access Tokens (PAT).
  2. In the Personal access tokens page, click the 'Add' button to create a new token.
  3. Use KAT PAT as the name, select 1 year for expiration, and leave the default All scopes selected for authorized scopes.
  4. Click 'Create Token' to generate your token.
  5. Copy the generated token value. Click the Settings button in KAT Command Center's app bar, paste the value into Personal access token and click Save.

KAT Credentials

The KAT Management site credentials enable CalcEngine Pipeline and Site Metrics. The Conduent (AMERICAS) network account enables Site Scope.

  1. Click the Settings button in KAT Command Center's app bar.
  2. Enter your KAT DataStore and/or your Conduent username and password.
  3. Click Save.
Test Credentials Before Saving

On the Profile page, Enter in one account's boxes signs in to just that account - the same check Save makes - and the modal stays open whatever the answer, so you can try a password without saving anything else. A sign-in that works is kept, exactly as it would be on Save; your other changes still wait for Save.

Remember my passwords

By default the KAT Management and Conduent passwords live in memory only, so each launch starts without them and the sections that need them say so. Turn on Remember my passwords on Profile and both are saved instead, and the app signs in with them silently on the next launch.

They are encrypted with Windows for your account, on this machine. Copied elsewhere, or read by another Windows user, the saved values are useless. What that does not protect against is anything already running as you, which is why it is off unless you turn it on.

Work Items > Queries
Order
The queries' order is the order of their entries in the rail and their chips on the Work Items page. Drag a query by its grip, or focus the grip and press Alt+↑ / Alt+↓; the new order is saved with Save.
Query ID and Name
Use the saved TFS query ID from its URL and choose the label shown in the rail and the Work Items header.
Severity threshold
Shows Critical and High counts in the Work Items header. Once their combined total reaches the threshold they are colored as ⊗ Critical Count and ⚠ High Count, and those items count on the query's rail badge. Clear to hide severity indicators.
Priority threshold
Shows Priority 1 and 2 counts in the Work Items header. Once their combined total reaches the threshold they are colored as ‼ Priority 1 Count and ! Priority 2 Count, and those items count on the query's rail badge. Clear to hide priority indicators.
Old threshold
Counts items unchanged for more than this many days and displays as ⟳ Old Count; they also count on the query's rail badge. Clear to hide.
Active within
When greater than 0, filters query results to items you revised within that many days. Clear to show all.

A TFS query can only ask about an item's latest revision (Changed Date, Changed By = @Me), so it can't answer "did I touch this in the last N days" - an item you worked yesterday drops out the moment someone else edits it, and an item you never touched shows up because you happened to be the last one in. Active Within instead reads each item's full revision history and keeps the item if any revision in the window is yours.

That accuracy costs one extra API call per item in the query. Every query makes that call eventually - it is the same read that fills in comments for the filter - but for the others it happens in the background after the grid is on screen, while this setting has to wait for it before the grid can be drawn at all. Answers are cached per item and reused until the item's changed date moves, which makes repeat refreshes nearly free, but the first run on a large query is noticeably slower - leave it clear unless the query is one you filter down this way. The query's severity, priority, old, and tag counts are all computed after this filter, so they describe your active items rather than the whole query.

Show tag counts
Shows KAT- prefixed tag totals under the Work Items header and lets those tags filter rows (useful to turn off when the majority of result rows have unique tags).
Hide query when no work items present
Leaves the query out of the rail while it has no items; it comes back as soon as the query finds one. The query you have open stays until you open another. On for a new query. A query saved before this option existed stays in the rail until you turn it on.
Exclude from What's Happening
Keeps this query's items out of the Dashboard's What's Happening list. Its rail badge still counts them. Off for a new query.
Tools > Grazer
Search roots
Named folders Grazer searches. Edit the names and paths for your machine; missing or inaccessible roots are reported without stopping the other roots.
Default file patterns
Filename wildcards, separated by semicolons, commas or line breaks, prefilled in Grazer's search form. The form's current patterns can be changed without changing this default.
Excluded folders
Literal folder paths excluded from traversal. The shared directory picker supports typing, immediate-child suggestions and the folder (Browse) button.
Excluded directory names and path fragments
Directory names match whole folder names; path fragments match anywhere in a path. Both lists are editable. Git metadata is controlled separately by its switch.
Maximum result rows
Bounds the results retained and shown; the default is 10,000, and it can be 1 to 100,000. A limit reached during a search is marked incomplete.
Maximum file / ZIP entry size (MB)
Bounds ordinary files and ZIP containers by their on-disk size, and ZIP entries by their uncompressed size. The default is 50 MB; 1 to 256 MB.
Search Git metadata
Includes folders named .git. Off by default.
Include ZIP files
Searches matching text entries without extracting or changing the archive. Off by default; entries are read-only.
Confirm before applying replacements
Adds a final confirmation after the mandatory preview. On by default; the confirmation can remember an opt-out, and this setting can turn it back on.
Tools > Repository Status
Repository roots
Folders searched for Git repositories, nested ones included. Each root has an optional name (the Show list on the Repository Status page offers {name} Repos, or the folder name when it has none) and a path; add and remove rows with the shared folder picker and the trash button. A missing root is reported without stopping the others. Changing the roots rescans on Save. The order of the roots is the order repositories are listed in on the page: drag a root by its grip, or focus the grip and press Alt+↑ / Alt+↓. Reordering alone does not rescan. Defaults: C:\BTR, C:\Windows\System32\drivers\etc and Visual Studio's XML schemas folder.
Ignore patterns
One case-insensitive .NET regular expression per line, tested against each folder path; a match skips that folder and everything under it. An invalid pattern is named under the box and nothing is saved on this page until it is fixed. Changing the patterns rescans on Save.
Check local status / Every (seconds)
How often each checkout's branch, changes and incoming and outgoing counts are read from disk. On, every 120 seconds (2 minutes), by default; 10 to 3,600 seconds. A value you saved before keeps its setting.
Fetch upstream remotes / Every (minutes)
How often the upstream remote of each checked-out branch is fetched. On, every 30 minutes, by default; 1 to 1,440 minutes. A value you saved before keeps its setting. Fetching never pulls or changes files. With either switch off, F5 still rescans and checks status.
Confirm Push, Pull, Sync and worktree cleanup
Each selected Git action asks before it runs. All are on by default and independent; a prompt's opt-out turns its switch off here, and you can turn it back on. Pull, Push and Sync ask one question naming the repository or how many there are. Commit always opens its review with the message field and changed-file list. A force push has no setting: it always opens its review and always carries its lease. With Confirm worktree cleanup off, cleanup still opens its review whenever anything needs force, a prune is involved or something cannot be removed, and every check (unchanged since the review, and, where force was not confirmed, locked, clean and a reason to go) still applies; see Cleaning up worktrees.
Connections > Release Pipeline Polling

Connections > Documentation
Documentation URL
Where Help and What's New open. Blank uses the published site. Must be an absolute https:// URL, or a file: URL to preview a local build of these pages; anything else is refused. Takes effect on the next Help or What's New open, with no restart.
