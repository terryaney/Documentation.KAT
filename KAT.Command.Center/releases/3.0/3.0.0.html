TFS Work Items Site Is Dead...

In KCC, you can now use one Create New dialog for Bugs, Tasks, Features, and Requirements, with KAT and configured tags plus attachments. In Work Item Detail, review Details, Related Work, Commits, Builds, and a streamlined History that traces state and ownership changes alongside each save. Switch to Edit Task to update the fields the KAT team uses, choose KAT, configured, or already-present tags, and stage attachment additions, removals, or replacements before saving.

Spec Sheet Magic shortens version updates: drop a valid workbook, and KCC finds its uniquely matching Spec Sheet task, opens it in Edit Task, updates the versioned title, and stages the replacement attachment. Review and save the proposed changes yourself; dropping the file does not save it. See Update a Spec Sheet by dropping it.

Notable Features

  • Paste screenshots into a new Work Item's description, an Edit Task comment, or a Return Triaged comment. Images upload when you save or return the item.
  • Open an image in Work Item Detail to zoom and pan, fit it to the window, view it at 100%, or open it in your browser.
  • Return Triaged keeps the dialog open when some updates fail, removes successful tasks, and leaves the remaining eligible tasks ready to correct and retry.
  • Work Item query navigation now gives Needs Action and Warning counts separate badges instead of combining them.
  • Work Item list mode adds a streamlined Tags filter picker.
  • Each query remembers its filter text, tags, indicator chips, and sort when you switch between queries.
  • The ⋯ menu before each row's ID replaces the right-click menu for Work Item actions.

A Unified Releases · Pipeline Page

Releases > Pipeline brings builds, release environments, cleanup, and commit comparisons together on one page. Follow a release through its environments, approve the next stage or redeploy where needed, and review the cleanup plan alongside the work being delivered.

Notable Features

  • The From and To release cards lead into commits grouped by repository, so you can see what changed without switching to a separate Release Differences page.
  • Open linked Work Items noted in commit comments directly from the Pipeline page without losing your focus or context.
  • From and To choices apply immediately and survive refreshes. From must be newer than To; an invalid pair keeps the previous comparison visible and pauses Pipeline refresh until you correct it or choose Restore comparison.
  • What's Happening rows let you approve the next environment or redeploy a stage directly, without first opening Pipeline. Approval chips for another site's release work without switching sites.
  • Show Pending includes newer release candidates, built work awaiting a release, and commits needing a build for both automatic and manually selected From/To comparisons, rather than only automatic mode.
  • For stages requiring approval, elapsed deployment time counts from approval to now while deploying, then from approval to finish. It no longer includes the potentially days-long wait after an environment becomes available to approve.
  • Partially succeeded stages now offer redeployment in both Pipeline and What's Happening.

Watch the RBLe Balancer

The new Sentinel > RBLe Balancer page shows how each balancer is spreading requests across its nodes right now: which nodes are healthy, how busy each one is and how fast it answers. Everything is read through Sentinel with your KAT Management credentials, whichever site is selected.

On the Dashboard, the RBLe Balancer tile counts nodes by state and shows each node's response time, CPU, memory, traffic share and gate. Step between balancers from its footer, or click it to open the page on that balancer.

Notable Features

  • Header chips count Healthy, Unhealthy, Offline and Unknown nodes; click one to show only those nodes. Balancer and Host choose which balancer to show and which web server to read.
  • Response Time and Traffic Share chart each node over time; click a node's icon in the table to hide or show its line.
  • The node table shows each node's state, traffic share, capacity, CPU, memory, request rate, response time and total requests, with details beside the list. Capacity shows each node's running and queued requests against its limits, and gate retries count how often a full node's requests were sent elsewhere.
  • Balancer Kings get actions to take nodes offline or bring them back online, on the chosen host or on all hosts, and to reset counts. Each action confirms what it will change first.
  • With a publishing node configured, View Settings downloads a node's appsettings file and opens it unless you turn automatic opening off, and Update Settings replaces that file on one node or every node in the cluster.
  • Add balancers, their hosts and publishing nodes under Settings > Sentinel · Balancer. What's Happening lists a balancer that is stale, unreachable, unhealthy or answered by an unknown host.
  • CalcEngines now uses a standardized, scrollable list with searchable filenames and checkout owners, sortable Name and environment-version columns, and shared filtering controls.
  • Manage opens the KAT DataStore management website with single sign-on (SSO) using your DataStore credentials. If automatic sign-in is unavailable or unsuccessful, the website opens for normal sign-in.
  • Control stale-checkout notifications under Settings > Releases: set when your checkouts turn red and when teammates' checkouts appear, or hide teammates' checkout notifications.
  • Open task references, including completed tasks, from CalcEngine History in Work Item Detail inside KCC. Closing the details returns to the same CalcEngine History and scroll position without leaving the app.
  • CalcEngines and Version History switch to compact card layouts in narrow windows, keeping versions, checkouts, and actions readable.
  • A temporary DataStore startup sign-in failure can be retried on refresh using remembered credentials, rather than asking you to re-enter credentials already saved.
  • Show marks upper-file checkouts that can block the TFS Release Pipeline in amber and newer upper versions that block QA in red. Blocked version tooltips explain the mismatch.
  • Checkouts do not prevent manual approval or promotion. Promotion warns before force-checking in an upper file held by someone other than you or the authority, and stops if that check-in fails.
  • Check Mine In now checks in only your files in the filtered rows, rather than all your checkouts.
  • Downloads use the original filename; DEV and UAT downloads no longer add _Test.
  • Changes to CalcEngine Patterns last for the current site selection; selecting a site again or restarting restores its catalog patterns.
  • Site Scope timestamps are all displayed in your local time zone.
  • Undo the last replacement. Grazer restores only the lines it wrote and leaves files changed since then untouched.
  • Searches scan every folder and keep up to 2,000 results, showing full totals and how many were left out. The Maximum result rows setting is gone.
  • A new Replace read-only files setting, and separate confirmations for line and file replacements, under Settings > Grazer.
  • A compact scan-details strip replaces the long status line; hover any count to see what it means.
  • Hide Inputs gives results more room, and Collapse All folds the results tree.
  • Custom file patterns last until you close the app; leave the box blank to use your Settings defaults.
  • Root problems show on the Grazer page instead of in What's Happening.
  • Refresh a single repository's local status without fetching. On Repository Status, F5 checks only listed repositories; use Rescan now under Background Checks to discover newly cloned repositories.
  • Set a default Commit message in Settings for single and batch commit reviews.
  • Show starts on Needs Attention; if nothing across your roots needs attention, it restores your last selected root when available.
  • A failed Pull started from What's Happening shows a dismissible Dashboard notice that opens Repository Status.
  • When a root is selected, the text filter matches names, branches and root-relative paths without the shared root path causing every repository to match.
  • A standardized KCC dropdown supports searchable filtering, keyboard navigation, and single or multiple selection where appropriate.
  • Improved rendering in narrow windows includes compact headers, wrapping controls, and card layouts where a full table would be difficult to read.
  • Long page contents scroll beneath their section headers, keeping the controls available.
  • From the Dashboard, open a Pipeline repository's commits or CalcEngines filtered by environment or checkout owner.
  • Diagnostics is now a Tools menu rather than a refresh-details page. It opens today's log or the log folder and saves a styled HTML snapshot of the current UI. Logs and snapshots are kept for 14 days; snapshots can contain information displayed on screen.
  • Pipeline Polling and Site Release Check settings moved from Connections to Releases; existing values are preserved.
  • Background thread processing improvements eliminating unrelated threads from blocking each other.
